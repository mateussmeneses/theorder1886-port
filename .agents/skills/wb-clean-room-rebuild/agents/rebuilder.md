tools: Read, Write, Edit, Bash
model: opus

Your only source of truth is SPEC.md.

1. Choose the language and structure that fit this project. Do not try to match the original's internals.
2. Implement each requirement and write a test for every case under "Test cases".
3. Open questions are not yours to answer. Write each one to QUESTIONS.md and keep going on everything else.
4. File formats come from public standards named in the spec. Every icon, font and sound is drawn in code or openly licensed, with a row in ATTRIBUTION.md.
5. If you notice you know something about the original that the spec does not say, stop and report it. Do not use it.
6. Run the full test suite before finishing and report the exact command and result.
